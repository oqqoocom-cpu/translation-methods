# 通用译审提示词

以下为方法模板。把真实文本、语种、定位、术语证据与任务规格填入私有项目；不在公开仓库填写。向任何外部服务提供文本前，先确认提供方和片段范围的授权。

提示词不含实际材料。模型输出是候选，不因为遵守格式就获得事实或质量认证。

使用前填写源语、目标语、读者、用途和文体；不默认译入中文或采用学术表达。文学、商务或技术文本的风格要求应显式给出，不能用于掩盖增译、漏译或含义改变。标准及以上流程使用经试译确认的风格说明；轻量流程在任务规格中写明必要的风格要求。

## 统一输出格式

译文按 [units Schema](../schemas/units.schema.json) 输出单元文件，`role` 为 `target`，单元编号与源文一致。审校和检查意见按 [findings Schema](../schemas/findings.schema.json) 输出发现，`origin` 填 `model`，`status` 固定为 `candidate`；`severity_suggestion` 只是建议。裁决候选按 [decision Schema](../schemas/decision.schema.json) 输出。程序检查与人工审校使用同一格式，可合并去重，示例见 [发现清单](../examples/findings.synthetic.json)。

## 忠实底稿

```text
任务：依据所给源文生成指定目标语的忠实底稿，不做未经授权的自由改写。
输入：源语、目标语、读者、用途、文体、已确认的风格说明、
稳定单元编号、必要上下文、已核验术语及适用范围。
约束：
- 保留主体、限定、否定、情态、因果、引文归属及作者立场。
- 数字、年份、单位、脚注和引文标记逐项对应，不补入背景判断。
- 无法辨认的字符、专名或多语片段列为待核，不猜补。
- 作者实际称谓与核验的实体名称不一致时，不静默改写作者。
输出：units 单元文件，role 为 target，单元编号与源文一致；
待核点写成发现，附原文定位。
禁止：宣称已核验来源、编造专家意见或自动关闭疑难。
```

## 独立忠实度审校

本提示词由另一模型、未继承翻译上下文的新会话或人工执行；同一模型同一轮自译自审不算独立审校。

```text
任务：先独立阅读源文，再检查底稿，不以流畅度抵消误译。
逐项检查：漏译、增译、主体、否定、因果、限定、情态、指代、
术语实体、引文归属、数字单位、脚注与表格层级。
每条疑点输出一条发现：family 为 FIDELITY，附单元编号、源文定位、问题代码、
严重度建议、理由、局部修改建议和所需证据；受影响范围写入 refs 或 detail。
不确定之处保持待核。无疑点只表示本轮未发现，不宣称全文无误。
```

## 术语抽取

```text
任务：从所给单元中提出术语与专名候选，不裁决译名。
输入：源语、目标语、稳定单元编号与文本、已有术语表及其状态。
输出：每个候选一条记录，status 填 candidate，含源文形式、类别、作用域、
候选译名和异译；另列出该候选出现的单元编号。
约束：
- 剔除普通词、数字年代、罗马数字、栏目值和并列或介词片段等噪声。
- 没有可核验来源时不填 evidence，不编造来源、标准或机构名称。
- 不修改已有条目的状态；与已有条目冲突时单独列出。
```

记录结构见 [term Schema](../schemas/term.schema.json)。`term_id` 和 `synthetic` 由项目填写；该 Schema 不含单元编号字段，出现位置在记录外单独列出。

## 风格试写

```text
任务：对同一试译单元写出 2 至 3 个风格变体，供责任人选定风格说明。
输入：试译单元、源语、目标语、读者、用途、文体和已知的风格要求。
输出：每个变体写明标签、目标读者、所用风格规则、译文和风险。
约束：
- 各变体忠实度相同，只在语域、句式、称谓和标点上不同。
- 不增删事实，不改变限定、情态和作者立场。
- 不推荐唯一答案，由人选定。
```

选定结果写入 [风格说明](style-guide.blank.json)。

## 目标语编辑

```text
前提：输入包括已通过忠实度审校的版本、已确认的风格说明和未决问题清单。
任务：在原意不变的前提下改进指定目标语表达，遵守风格说明、读者与文体要求，
只提出必要的局部差异，不默认改成学术或文学表达。
禁止：增加事实、删除限定、改变作者立场、合并不同主体、
改动已锁定术语或通过补写背景消除原文含混。
每条建议输出一条发现：family 为 STYLE，旧表达和可能影响的检查项写入 detail，
附理由与编辑建议。
所有建议仍须回到源文复核；不得直接覆盖冻结稿。
```

## 疑难裁决与回归

```text
输入：原文定位、不同意见、可核验证据、术语作用域及规则。
任务：区分事实、建议和未解决冲突，提出范围明确的裁决候选。
输出：按 decision Schema 的裁决候选，含理由、证据、影响单元和同类回归清单；
status、decided_by 和 decided_at 由责任人填写，修改版本记入相关问题记录。
证据不足时继续待核，不通过投票、模型共识或回译强行关闭。
修复后回查源层、正文、术语、引文、表格、索引、版式及续接。
```
