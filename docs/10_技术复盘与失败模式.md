# 技术复盘与失败模式

这里整理流程层面的风险与应对，不包含实际项目名称、文本片段、页码、专家意见或运行记录，也不以这些建议宣称完成了质量评测。

| 失败模式 | 为何容易漏过 | 建议处理 | 验收边界 |
|---|---|---|---|
| 把最大版本号当最终稿 | 文风、排版、样章和正式交付不是同一版本序列 | 分开记录范围、状态、批准与哈希 | 候选通过不等于正式晋升 |
| 续接摘要仍引用旧版本 | 正文修订后，入口与交付清单没有同步 | 使用稳定编号、精简当前导航和原始证据定位 | 摘要不替代原记录 |
| 一份旧门禁否定所有后续授权 | 同一事项的后续批准与更广范围的许可混在一起 | 按时间、对象与授权范围解释门禁 | 阅读批准不扩大为印制或传播许可 |
| 结构完整但语义改变 | 数字与段落计数无法发现否定、因果和主体错误 | 命题级忠实度检查；高风险全审 | 确定性检查不能替代语义审校 |
| 术语短串替换误伤 | 同姓、缩写、嵌套称谓和历史同名可能碰撞 | 明确实体关系与最长完整跨度，保留作用域 | 不无依据补入身份 |
| 中文编辑悄悄改论证 | 顺滑表达掩盖增译、限定消失和因果漂移 | 忠实度先行、差异修改、回到源文复核 | 文风通过不能抵消忠实度问题 |
| 多语抽取损坏后模型补字 | 看似合理的字符可能并非原文 | 返回页面证据，不可辨者留置；按条件核验平行文本 | 平行转译不冒称源语直译 |
| 文件哈希与规范化哈希混用 | 同名算法可针对不同输入 | 明示字节 SHA-256 与规范化 JSON SHA-256 | 历史快照不证明现时文件一致 |
| 相同 PDF 被直接去重 | 相同字节可能承担不同校样和交付角色 | 先记录用途及引用再考虑归档 | 重复不是删除许可 |
| 临时目录当作垃圾 | 页图、裁剪和校样可能是审校证据 | 先核引用、可重生成条件和完整路径 | 名为临时不等于可清空 |
| 构建只能在原机器成功 | 绝对路径、外部字体与工具版本未登记 | 区分取回文件、读取结构、独立构建和视觉验收 | 同盘副本不是独立备份 |
| 私有目录直接初始化 Git | 忽略文件不清除已经提交的历史 | 独立目录、逐文件导出、全新历史 | 内容扫描还需人工权利复核 |

## 改进是否有效

一次改进应明确问题、范围、版本和验收证据。旧问题修复后检查受影响下游；同类错误回归、抽样扩大及整书回查的触发条件参见 [质量控制](04_质量控制与回归.md)。

流程建议、工具实现和实际效果分别描述。没有专家校准样本与评价记录时，不给出准确率或模型优劣排名。修复一条疑难并不证明所有相似单元都已正确。
