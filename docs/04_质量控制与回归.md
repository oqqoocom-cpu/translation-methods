# 质量控制与回归

## 分层审校

忠实度、术语专名、受保护要素和目标语编辑分别进行；书籍或印刷交付另加适用的排版终校。受保护要素包括数字、单位、标记和结构，学术材料另含引文、脚注等。独立审校者先读源文，再看译文。独立审校者是另一模型、未继承翻译上下文的新会话或人工；同模型同一轮自译自审不能替代独立检查。

高风险内容包括核心结论、直接引文、争议史实、政治法律宗教概念、罕见专名、多语片段，以及技术安全说明、合同义务等误译后果重大的内容。必须保留源文、查可核验来源并由责任人裁决；必要时由掌握相应语种或领域的专家复核。模型意见一致不能绕过这道门。无法核实者仍为待核，不能写成通过。

## 全量与抽样

结构、漏段、重段、数字、年份、百分比、单位、公式、引文标记、脚注、表格结构和锁定术语实行全量检查；长篇或批量材料使用程序检查，短文本可人工逐项核对；页码只在固定页面材料中核对。程序只能发现预设错误，仍须检查输入和规则本身。表题必须联动表号、列名、行内容、章节论证及相近表题，保留层级与统计口径差异。

可机械比对的部分由 `tools/check_translation.py` 完成，检查项与局限见下文“程序检查”。程序发现一律为候选问题，经人确认后才登记为问题记录。

语义检查以可独立判断的命题、限定、因果、否定、情态与指代为原子单元。低风险使用有记录的分层随机抽样，覆盖文件或章节、文体和模型批次；高风险全部复核。发现主要或严重错误，扩大同类检查；系统性错误触发全项目回查。

完整级项目比较模型、平台或流程，替换正式流程，或对外作质量结论时，需要基准集；其他等级作质量结论时，按相同样本、相同规则对照并写明适用范围。基准集使用经专家校准的原子语义单元，采用 MQM 启发的错误类型与严重度并进行盲评。规模按语种、文体、风险和比较目标确定并记录理由；长篇项目可采用 300 至 600 个单元作为建设目标，不把这一数量强加给短文本任务，也不代表本库已经拥有这样的基准集。自动分数和回译只用于发现疑点，不是准确性的证明。

## 程序检查

对照检查器读取源文与译文两份单元文件，按单元编号对齐，输出发现报告；结构见 [units Schema](../schemas/units.schema.json) 和 [findings Schema](../schemas/findings.schema.json)。`--checks` 选择检查组，默认全部运行；`--length-factor` 设定长度偏离倍数，默认 2，须大于 1。

| 检查组 | 问题代码 | 类别 |
|---|---|---|
| `structure` | `unit-missing`、`unit-extra`、`unit-order`、`duplicate-unit-id`、`target-empty`、`target-untranslated`、`target-duplicate`、`repeat-inconsistent`、`length-outlier` | `STRUCTURE` |
| `numbers` | `number-missing`、`number-extra` | `PROTECTED` |
| `symbols` | `symbol-missing`、`symbol-extra` | `PROTECTED` |
| `markers` | `marker-missing`、`marker-extra` | `PROTECTED` |
| `terms` | `term-missing`、`term-alternate`、`term-pending`、`entity-missing`、`entity-pending` | `TERMS` |

比较前先作 NFKC 规范化。网址、邮箱、标签、占位符、格式符和方括号数字引文标记先行提取、逐项比较，其中的数字不再重复计数。数字按数值和次数比较，年份与百分比包括在内；小数点按每份文件的 `decimal_mark` 读取。数字后紧接或隔一个空格的“万”“亿”“万亿”及繁体“萬”“億”“萬億”按数值换算，“3.5万”与“35,000”记为同一个值。单位符号须紧接数字或隔一个空格。长度偏离按非空白字符比例计算，超出全文中位数的 2 倍或不足其一半时报出；可比单元少于 5 个时跳过，报告记为 `too-few-units`。

术语检查只强制核对 `locked` 术语和带 `decision_id` 的实体：锁定译名没有出现报 `term-missing` 或 `entity-missing`，登记的异译混入报 `term-alternate`。其他状态只报 `term-pending` 或 `entity-pending`。`rejected` 和 `deprecated` 术语、没有候选译名的实体不参与比较；不加 `--glossary` 时跳过整个术语组。所有发现的 `status` 都是 `candidate`。

退出码 0 表示已运行的检查未发现问题，1 表示有候选问题，2 表示输入无效、缺少依赖、报告文件已存在或没有任何检查得以运行。屏幕只显示计数、单元编号、问题代码和相关编号，不回显原文或译文；`--report` 把完整结果写入新文件，报告留在私有项目。

已知局限：

- 月份名称、拼写数字和“十四”这类中文数字不识别。
- 计数单位只在紧跟阿拉伯数字时换算：“3万5千”只换算“3万”，“5”单独计数。
- “千”和“百”不作计数单位，以免把“5千米”读作 5000；“兆”的数值因地区而异，也不换算。
- 英文 thousand、million、billion 不换算：“3.5 million”只记为 3.5，与“350万”比较时会报出差异。
- 空格分组的数字、上标和省略整数位的小数可能误报。
- 术语只要求词首对齐，短缩写可能匹配到更长的词。
- 公式、表格结构、脚注内容、页码和著者-出版年制引文中的人名不在检查范围内，须另行核对。
- 数字一致不证明含义正确。

## 错误与关闭

`critical` 改变核心事实、结论或引文归属，一项即退回相关阶段；`major` 改变局部含义，须修复后再放行；`minor` 不改变主要意义，进入编辑队列；`preference` 不计作准确性错误。

问题的 `fixed` 表示修复候选且具备通过的回归证据，`closed` 还需责任人确认。严重或系统性问题记录根因、影响版本、修复版本、规则及同类回归，不只修被抽中的一句。

更改源层、模型、提示词、术语、编辑或版式后检查受影响下游。模型或流程升级时，已有固定基准的先跑基准；没有基准的，轻量级和标准级项目至少用同一试译样本比较新旧流程，完整级项目先按上文建立基准集再决定是否替换；新流程不如旧流程时不替换正式流程。语义报告的 `passed` 不等于发布或出版授权，也不等于全文每一处绝对无误。

## 数字声明

准确率必须交代定义、分母、抽样方法、统计假设、评价者、版本和剩余风险。不在公开文档沿用未经复核的“99%”或优于某平台的宣传。严重错误数和未解决高风险项分别报告，不能隐藏在平均分中。
