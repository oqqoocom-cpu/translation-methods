# 受控修改与续接

## 唯一续接入口

每个私有项目维护一份精简恢复清单，记录任务目标、当前规范源、正式阶段、冻结文件及哈希、未决问题、已裁决变更、下一动作和禁止动作。必要时按稳定编号读取详细证据，不把所有历史文件堆入上下文。

文件名最大版本号、最新修改时间和“已生成”都不能证明正式版本。只有清单引用并通过相应回归的产物才是当前正式入口。完整日志与历史证据仍保留，摘要不是替代品。

## 修改链

1. 登记原因、权限、旧版本、目标单元和影响范围。
2. 构建新版本，保留差异，不原位改写冻结文件。
3. 检查上下游：源层、术语、正文、引文、表格、索引、版式与质量报告。
4. 更新交付清单、正式哈希、规则快照和恢复清单。
5. 完成回归和责任人确认后，才推进阶段与正式入口。

构建完成但清单链未同步时，状态为 `built-pending-chain-sync`，不能当作正式完成。续接不能只更新一句“已完成”而留下旧交付版本、旧哈希或旧问题状态。

## 归档原则

冻结是防止意外漂移的约定与核验机制，不等于独立备份。独立备份需另行选择位置、检查恢复能力及保密边界。

精确重复、缓存和旧版本先登记依赖，再建议冷归档。渲染页可能证明检查，旧版本可能支撑裁决；未经确认不删除或移动。长期保留正式交付、源基线、裁决、关键回归和可恢复状态。
