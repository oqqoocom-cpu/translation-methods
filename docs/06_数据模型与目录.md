## 结构与语义门槛

`common` 提供编号、作用域与证据结构；`term`、`entity`、`decision`、`issue`、`quality-report`、`registry` 和 `application` 各有独立 Schema。JSON Schema 检查字段及状态依赖，程序补充重复规则、覆盖计数等跨字段约束。

来源记录包含类型、标识、定位和核验日期。虚构证据使用 `synthetic` 标记，仅供演示；标为真实通过的质量报告不得把虚构来源视作核验依据。证据 ID 本身并不证明来源内容真实，须由审核者在私有项目核验。

## 哈希约定

文件完整性使用原始字节 SHA-256。规则同步使用排序键、无额外空白的规范化 JSON SHA-256，明确记录 `canonical-json-v1`；它对空格排版变化不敏感，不能与字节哈希混用。冻结版本的字节哈希仍要保留。

规则应用快照逐条登记适用状态和验收状态。不适用或例外须有理由，不能删去规则造成“全部通过”假象。空白模板状态为 `draft-template`，有意不符合完成记录 Schema；填完并另存后才验证。

电子表格界面、JSON 和数据库应共用稳定编号及版本源，不各自独立裁决。这里仅提供结构示范，未实现表格数据库双向同步、全文翻译引擎或语义自动审校。
