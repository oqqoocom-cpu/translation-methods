# 数据结构与目录

公开库保存方法、规则、结构和虚构示例。实际工作数据另建私有项目，不置于公开仓库中。

```text
public-method-library/
  docs/
  registry/
  schemas/
  templates/
  examples/
  tools/
  tests/

private-project/
  intake/
  source-baseline/
  context/
  terms-and-entities/
  translation-layers/
  reviews-and-decisions/
  layout/
  delivery/
  regression/
  recovery/
  management/
```

私有项目中，以下目录对应本库的记录：

- `source-baseline/`：原件、字节哈希和源文单元文件
- `context/`：风格说明
- `terms-and-entities/`：术语与实体记录
- `translation-layers/`：译文单元文件
- `reviews-and-decisions/`：发现清单、问题与裁决
- `delivery/`：交付清单和质量报告
- `recovery/`：恢复清单
- `management/`：目录约定、批次清单、阶段文件盘点和成本表

单元文件可用 [对照检查器](../tools/check_translation.py) 核对，检查项见 [质量控制与回归](04_质量控制与回归.md) 的“程序检查”一节。

## 结构与语义门槛

`common` 提供编号、作用域与证据结构；`term`、`entity`、`decision`、`issue`、`quality-report`、`registry`、`application`、`units` 和 `findings` 各有独立 Schema。JSON Schema 检查字段及状态依赖，程序补充重复规则、覆盖计数等跨字段约束。

`units` 保存切分为稳定单元的源文、中转语文本或译文，源文与译文用相同的单元编号对齐。`findings` 记录程序、模型或人工审校的发现，状态固定为 `candidate`；经人确认后另建 `issue` 记录，才进入问题的修复与关闭流程。

术语与实体用 `target_language` 和 `candidate_target` 记录目标语及候选译名，不限于中文；填写候选译名时必须注明目标语。

来源记录包含类型、标识、定位和核验日期。虚构证据使用 `synthetic` 标记，仅供演示；标为真实通过的质量报告不得把虚构来源视作核验依据。证据 ID 本身并不证明来源内容真实，须由审核者在私有项目核验。

## 哈希约定

文件完整性使用原始字节 SHA-256。对照检查报告逐一记录各输入文件的字节哈希，使检查结论能对应到具体文件版本。规则同步使用排序键、无额外空白的规范化 JSON SHA-256，明确记录 `canonical-json-v1`；它对空格排版变化不敏感，不能与字节哈希混用。冻结版本的字节哈希仍要保留。

规则应用快照记录 `process_tier`，保留该等级的全部规则并逐条登记适用状态和验收状态；验证工具拒绝规则集合与等级不符的快照。不适用或例外须有理由，不能删去规则造成“全部通过”假象。空白模板状态为 `draft-template`，有意不符合完成记录 Schema；填完并另存后才验证。

电子表格界面、JSON 和数据库应共用稳定编号及版本源，不各自独立裁决。这里仅提供结构示范，未实现表格数据库双向同步、全文翻译引擎或语义自动审校。
