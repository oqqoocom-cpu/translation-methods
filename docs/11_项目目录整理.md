# 项目目录整理

整理先解决“从哪里进入、什么状态、依据是什么”，再决定是否迁移文件。公开方法与私有资料分开；不要求把历史工作区搬完，才能公开通用方法。

## 日常导航

项目主入口保持精简，指向当前规范、正式交付、候选、未决问题及下一步。完整历史另存，导航不复制全书或全量日志。登记的是用途与批准，不按文件名或修改时间选最终稿。

| 层 | 保存内容 | 公开边界 |
|---|---|---|
| 通用方法库 | 文档、空白模板、纯虚构示例、原创通用工具 | 单独审核后考虑公开 |
| 私有工作区 | 原书、源层、译稿、术语实体、审校与排版 | 不进入方法仓库 |
| 私有整理记录 | 路径映射、依赖、哈希、问题队列、操作记录 | 不进入方法仓库 |
| 历史与缓存 | 历史版本、页图、构建产物和运行缓存 | 按用途核验，不按名称一键删除 |

## 有限清理

1. 记录源目录及逐文件现时哈希，识别软链接、目录跳转与边界。
2. 核对交付、审校、动态构建与静态引用。未观察到引用不等于不存在依赖。
3. 对明确无证据用途、保留源码且可重生成的运行缓存，限定具体范围并取得操作授权。
4. 优先可撤回迁出而非删除，保留原相对路径、目标路径和哈希。已有目标拒绝覆盖。
5. 检查预期迁出与新增，确认其他文件字节及原有入口不变。保存操作后基线。

不能证明可重生成的页图和版式产物继续保留。正式文件、待核版本、字体与专家记录不因文件数多而降级。

## 可撤回迁移

反向迁回前检查原路径是否重新生成、历史副本是否仍一致，发生冲突就停下。路径搬动可能影响脚本与绝对引用；需要同步的迁移应单独安排，不把一份新导航当作构建链已修复。

独立备份、文件恢复与跨机器重建各自解决不同风险。公开方法无需复制原书，但涉及私有文件搬动时，操作范围、风险与保留策略仍须明确。
